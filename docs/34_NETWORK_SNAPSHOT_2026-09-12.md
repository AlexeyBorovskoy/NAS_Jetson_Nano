## 3. Перенос второго узла — главный результат дня

Узел `living_room` стоял через две и более стен от главного. Приложение Deco при этом
показывало **«сигнал хороший»**. Замер показал обратное.

| Второй узел, один и тот же тест | До переноса | После переноса |
|---|---|---|
| HTTP-обращений успешно из 10 | **6** | **10** |
| Среднее время ответа | **746 мс** | **53 мс** |
| Худшее время ответа | **4023 мс** | **63 мс** |
| ICMP, ответов из 10/20 | **1** | **20** |
| ICMP, среднее | **1479 мс** | **2.7 мс** |

Для сравнения главный узел `hallway` в тот же момент: 10 из 10, среднее 77 мс.

Побочный эффект для рабочей станции, которая после переноса стала цепляться к
`living_room`:

| Показатель станции | До | После |
|---|---|---|
| Уровень сигнала | 36–42 % | **80–85 %** |
| Скорость радиоканала (TX/RX) | 40–175 Мбит/с | **866.7 Мбит/с** |

**Вывод:** у Deco E4 нет выделенного радио под транзит, клиенты и backhaul делят один
эфир. Узел раздаёт ровно то качество, которое получает сам. Перестановка дала больше,
чем любая настройка.

## 5. Прошивки Deco E4 V4

Оба узла были на **1.0.0 Build 20230307 Rel. 56271** (март 2023). Облако предлагало
1.2.0, при этом онлайн-загрузка зависала на `Downloading... 0 %`.

Каталог TP-Link для этой ревизии — `support/download/deco-e4/**v4**/` — содержит восемь
версий: 1.0.0, 1.0.2, 1.1.0, 1.1.1, 1.1.2, **1.2.0**, **1.2.2**, **1.3.1**.

🔴 **Прямая заливка 1.3.1 поверх 1.0.0 отвергается** устройством:
`Upgrade failed. Please select the latest version of firmware to upgrade.`
Причина видна в именах файлов: 1.2.2 помечена `US_EU_RSA2048_up`, 1.3.1 — `RSA2048_up`.
Это переход на новую схему подписи, и прошивка 2023 года её не понимает.

**Рабочая цепочка:** `1.0.0 → 1.2.0 → 1.2.2 → 1.3.1`, на каждой ступени сначала
второстепенный узел, затем главный.

Отказ **безопасен**: устройство не начинает запись, версии в таблице не меняются.

## 6. Восемь ловушек этого дня

Каждая один раз увела диагностику в сторону. Записаны, чтобы не повторять.

1. 🔴 **Индикатор «сигнал хороший» в приложении Deco не означает работающий транзит.**
   Приложение меряет уровень сигнала, а не потери и не пропускную способность. При
   «Good» узел отвечал в 6 случаях из 10 со средним 746 мс. Мерить TCP, а не смотреть
   на шкалу.
2. 🔴 **По ICMP о узле судить нельзя.** До переноса узел терял 90 % пингов, но HTTP при
   этом проходил. Вывод «узел мёртв» был бы неверен; вывод «узел здоров» — тоже.
3. **Узел меняет IP при перезагрузке.** `living_room` после обновления переехал
   `.250 → .249`, рабочая станция `.103 → .102`. Проверка по прежнему адресу дала
   «все 10 отказов» и выглядела как поломка.
4. 🔴 **После обновления веб-интерфейс Deco уходит на HTTPS.** `http://192.168.68.1`
   отвечает `307 → https://…:443`. Проверка, ожидающая 200 по HTTP, объявляет узел
   мёртвым. Узел при этом полностью жив.
5. **`Invoke-WebRequest` в PowerShell занижает скорость скачивания в разы.** Первый
   замер дал 10 Мбит/с, `curl` на том же канале в ту же секунду — 53–80 Мбит/с. Для
   замеров пропускной способности использовать `curl`, а не командлет.
6. **Резолвер отдаёт AAAA первой, и тест доступности врёт.** `getent hosts` вернул
   IPv6-адреса TP-Link, соединение по ним ушло в таймаут, и картина выглядела как
   блокировка. По IPv4 всё было открыто. Проверять `getent ahostsv4`.
7. **У TP-Link `deco-e4` и `deco-e4r` — разные каталоги, а `v4` и `v4-40` — разные
   страницы.** Поиск в каталоге `deco-e4r` дал «для V4 файлов нет нигде» (проверено
   семь регионов). Правильный каталог `deco-e4`, страница `v4`, где лежат все восемь
   версий. Утверждение было шире проверенного и оказалось неверным.
8. 🔴 **Под AmneziaVPN приложение Deco не видит собственную домашнюю сеть.** На
   телефоне приложение писало `Невозможно подключиться к Deco` и выглядело так, будто
   узел пропал из системы. На деле оба узла были на схеме, связь между ними зелёная, а
   трафик через «пропавший» узел шёл на 866.7 Мбит/с. Причина: на Android в туннель
   уходит **весь** трафик, включая локальные адреса; на рабочей станции этого не
   видно, потому что там в туннеле прописано исключение для домашних подсетей.
   Симптом опознаётся по значку VPN в статус-баре телефона. Родня записанным граблям:
   отрицательный результат не называет причину.

## 7. Открытое

- **Скан эфира не сделан.** Windows отдаёт список BSSID только при разрешённой
  геолокации (сейчас `Deny`, прав администратора в сессии нет), телефон по USB в `adb`
  не появился. Поэтому не подтверждено, на каком диапазоне держится транзит между
  узлами и насколько забит канал соседями.
- **EC220 продолжает раздавать Wi-Fi** и конкурирует с mesh за тот же эфир. Решение
  (погасить и перевести клиентов либо развести каналы) не принято.
- **Узлы остались на разных версиях:** `hallway` 1.2.0, `living_room` 1.0.0.
- **Кабельный backhaul исключён** владельцем: только радио.

### Чем это грозит системе — честная оценка

**Данным и работе NAS — ничем.** Deco не участвует в хранении: дампы 12.09 03:04,
вторая копия Immich 12.09 04:20, диски 6 % и 77 %, таймеры и туннель активны, все
13 контейнеров работают, все сервисы доступны из Wi-Fi (8080, 2283, 8090, 8099, 445,
3001, 19999, 22).

Остаются три несрочных риска, все — от старой прошивки дочернего узла:

1. **Безопасность.** Узел без исправлений с марта 2023. Наружу не смотрит, достать его
   можно только из домашней сети или по воздуху в пределах квартиры. Риск невысокий,
   но растёт со временем.
2. **Несогласованность узлов.** Разные версии в одной mesh — не штатный режим. В этот
   день был **необъяснённый** эпизод: станцию сбросило на 2.4 ГГц, скорость упала
   вшестеро, затем вернулась сама. Связь с расхождением версий **не установлена**, и
   выдавать догадку за причину нельзя.
3. **Доставка настроек.** Пока узел выпадает из управления, новая конфигурация может
   до него не доходить. Практический вывод: **до переподключения узла не менять имя
   сети и пароль Wi-Fi** — дочерний узел рискует остаться со старыми и отвалиться.

## 8. English summary

**Why:** the owner reported slow internet on the phone over the Deco mesh.

**Root cause:** node placement, not the ISP link. The wired path is healthy (87–92 Mbit/s,
0.4 ms to the gateway). The second Deco node stood two or more walls away, and the Deco
app still reported a "good" signal.

**Measured, second node, same test before and after relocation:**

| Metric | Before | After |
|---|---|---|
| HTTP requests OK of 10 | 6 | 10 |
| Mean response | 746 ms | 53 ms |
| Worst response | 4023 ms | 63 ms |
| ICMP replies | 1 of 10 | 20 of 20 |

The workstation, which then associated with that node, went from 36–42 % signal and
40–175 Mbit/s to **85 % and 866.7 Mbit/s**.

**Speeds:** wired 87–92 Mbit/s; Wi-Fi bypassing the VPN 64–80; Wi-Fi through AmneziaVPN
46–53 with one run of four collapsing to 0.8. DNS via Deco averages 73 ms against 4 ms
straight from the EC220.

**Firmware:** both nodes were on 1.0.0 (March 2023). Flashing 1.3.1 directly is rejected
because 1.2.2 and 1.3.1 carry `RSA2048_up` signatures. Working chain:
`1.0.0 → 1.2.0 → 1.2.2 → 1.3.1`. The refusal is safe, nothing is written.

**Hardware note:** the Deco E4 has no dedicated backhaul radio and 100 Mbit/s ports. A
node delivers exactly the quality it receives, so placement dominates every setting.

**What the main-node upgrade bought:** DNS through the Deco fell from 73 ms to **7 ms**,
Wi-Fi throughput rose from 64–80 to **100 Mbit/s**, and the web UI moved to HTTPS.

**Child node cannot be upgraded by any available path.** The cloud check fails in the app
(their own FAQ link returns 404), the cloud download stalls at 0 %, and a local file
always lands on the main node regardless of the `Device Model` selection. The route to
TP-Link itself is healthy — five cloud and file hosts answer on 443 from the wired link.
Re-adding the node in the app is the remaining option: a joining node receives firmware
from the main node locally, without the cloud.

**Session-hold test — a negative result.** Two 20-minute sessions, one through
AmneziaVPN and one bypassing it over the same Wi-Fi, both completed: 1172 s each,
60 MB each, no drop. Duration alone does not kill a session. The test was rate-limited
to 50 KB/s, so it checked duration but **not** load or traffic pattern.

**Trap worth repeating:** under AmneziaVPN the Deco app cannot reach its own home
network on Android — everything goes into the tunnel, including local addresses. It
looks exactly like a node that vanished from the mesh, while that node is in fact
carrying clients at 866.7 Mbit/s.

**Risk to the system: none for data.** Backups, disks, timers and all NAS services were
verified healthy. Three non-urgent risks remain from the child node's 2023 firmware:
unpatched security, an unsupported mixed-version mesh, and configuration that may not
reach the node — so do not change the Wi-Fi name or password until it is re-added.
