# Память разговора @бобик — дизайн / @bobik conversation memory — design (2026-09-19)

> 🇷🇺 Утверждено владельцем 2026-09-19. EN summary — в конце.
> Статус: **спецификация**; реализация — после плана; выкат — только по «деплой».

## 1. Зачем и что считается готовым

Бобик отвечает на каждое сообщение с нуля: «бобик, что приготовить?» → ответ → «бобик, а без мяса?» —
и он не понимает, о чём речь. Семье нужен разговор, а не справочное окно.

**Готово, когда:** в группе «Боровские» Оля спрашивает «бобик, что приготовить на ужин?», Ваня пишет
«бобик, а без мяса?» — и ответ учитывает предыдущий вопрос. «бобик, забудь» начинает с чистого листа.

## 2. Решения владельца

| Вопрос | Решение |
|---|---|
| Чья память в группе | **одна общая нить группы** (Бобик знает, кто что сказал); в личке — своя у каждого |
| Срок и место | **последние 10 реплик, забывает после 30 мин тишины, только в оперативной памяти** — на диск не пишется, перезапуск = чистый лист |
| Подход | память в боте, история передаётся в поле `context` шлюза — шлюз не меняется |

Отвергнуто: память в шлюзе (сессии — новый интерфейс, память в другом контейнере); многоходовой диалог
ролями в API GigaChat (переделка шлюза и всех провайдеров ради малозаметной разницы).

## 3. Схема

```
Telegram / Talk ─► talk_bot.answer(question, user, dialog=(ключ, имя говорящего))
                      ├─ safety gate — судит только НОВЫЙ вопрос
                      ├─ context = DialogMemory.history(ключ)   «Олечка: …\nБобик: …»
                      ├─ шлюз /v1/chat {prompt, context, user}  → redact(full) → GigaChat
                      └─ DialogMemory.add(ключ, имя, вопрос) + add(ключ, "Бобик", ответ)
```
Шлюз уже фильтрует весь запрос вместе с `context` (`safe_full = redact(full)`, проверено 2026-09-19),
квоты на человека считаются по полному объёму токенов.

## 4. Компоненты

| Компонент | Ответственность |
|---|---|
| `app/dialog.py` — `DialogMemory(max_turns=10, idle_ttl=1800, max_chars_turn=500, max_chars_total=3000, clock=time.time)` | `add(key, speaker, text)`, `history(key) -> str`, `forget(key)`; истёкшие разговоры удаляются при обращении; старые реплики вытесняются первыми; один экземпляр на процесс (`MEMORY`) |
| `talk_bot.answer(question, user, dialog=None)` | `dialog = (key, speaker)`; при ответе из облака (путь «chat» через gate) — история в `context`, после ответа — две реплики в память. Отказы gate, уточнения, домашние инструменты, ошибки шлюза — в память не пишутся |
| `talk_bot._ask_llm(question, user, context="")` | передаёт `context` в шлюз |
| `telegram_bot` | ключ `tg:<chat_id>`, говорящий — `first_name` из Telegram (иначе логин); команда «забудь» |
| Talk-цикл | ключ `talk:<room>`, говорящий — имя из Talk (`actorDisplayName`, иначе логин) |

## 5. Поведение

- В память попадают только обращения к Бобику и его ответы. Сообщения без обращения, как и раньше,
  не читаются и не хранятся. Закачки («скачай», «закачки», «отмени N») в историю не пишутся.
- «бобик, забудь» (и «забудь» в личке) → `forget(ключ)` → «🐕 Забыл, начнём сначала.»
- Группа и личка, разные комнаты Talk — независимые разговоры.
- Лимит ответов на человека в сутки и бюджеты шлюза не меняются.

## 6. Ошибки и безопасность

- Память только в процессе; на диск и в журнал текст разговоров не пишется (в журнале — метаданные: кто,
  размер истории в символах).
- История проходит фильтр личных данных шлюза вместе с вопросом.
- Цена: вопрос с историей тратит больше токенов (до ~3000 символов истории сверху) — лимиты шлюза действуют.
- Safety gate не видит историю: опасная просьба, разбитая на реплики, проверяется по каждой новой реплике
  (как и сейчас).

## 7. Тесты

- `DialogMemory`: предел 10 реплик; забывание через 30 мин тишины (подменённые часы); `forget`; обрезка
  реплики и общий предел; разные ключи не смешиваются.
- `answer`: история уходит в `context` (подменённый `_ask_llm`); после ответа — две реплики; отказ gate и
  домашний инструмент историю не пополняют; без `dialog` поведение прежнее.
- `telegram_bot`: группа — один ключ на чат, говорящие различаются; личка — свой ключ; «бобик, забудь»;
  закачки в память не попадают; сообщение без обращения в память не попадает.
- Talk: ключ по комнате (регрессия `tests/nas_api`).

## 8. Выкат (по «деплой»)

Пересборка NAS API (≈15 с простоя), `telegram connected` в журнале, проверка в группе: вопрос → уточнение
без повтора темы → «бобик, забудь». Правило №13 не затрагивается (VPS не меняется).

### EN summary
Conversation memory for @bobik. The family group shares one conversation thread in which the bot knows who
said what; each direct chat and each Talk room has its own. The bot keeps the last 10 turns in process memory
only and forgets a conversation after 30 minutes of silence or on "бобик, забудь"; nothing is written to disk.
The history is sent through the gateway's existing `context` field, so the gateway, its PII redaction and its
per-person quotas are unchanged. Only messages addressed to the bot and its answers are remembered; downloads,
gate refusals and home tools are not. The safety gate still judges only the new question.
