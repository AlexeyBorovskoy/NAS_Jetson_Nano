## Храповик (стадия 8) — как встроить, а не построить рядом

- Ворота уже есть: `.githooks/pre-commit` → `scripts/quality/preflight.sh`, CI `quality-checks.yml`.
  Новая проверка — режим `code_metrics.py --check docs/audit/2026-10-02_code_audit/baseline.json`
  внутри `preflight.sh`, а не отдельный workflow.
- Правила проверки: (1) число файлов в `fail` не растёт; (2) изменённый файл, уже нарушающий
  порог, не ухудшает свои `cc_max`, `func_loc_max`, `broad_catch+silent_catch`; (3) новая функция —
  CC ≤ 10, длина ≤ 40; (4) исключение — явный `--allow-regression <файл> --reason "…"`,
  видимый в истории.
- Проверка на себе: ветка с намеренным нарушением → `preflight.sh` и CI красные; без этого
  стадия не закрыта (правило №14: «проверка без истории дефекта — балласт»).
- Предохранители в `CONTRIBUTING.md`: новая команда бота — новая функция в `app/services/`,
  а не ветка в `_dispatch`; тексты — в `app/texts.py`; новая копия «где лежит `.env`» запрещена,
  только `layout.sh`/`nas_layout.py`.
