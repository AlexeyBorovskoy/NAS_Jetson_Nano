## Разбор замечаний и ответы

### 1. vvzvlad: «Зачем JetPack, если ускоритель не используется?»
**Справедливо по факту:** GPU Nano сейчас простаивает — проект работает как обычный x86-NAS.
**Ответ:** Смысл Jetson именно в CUDA-ядрах. План — дать GPU полезную нагрузку, совместимую с CUDA 10.2 (см. Фаза 5): локальное распознавание/векторизация в Immich (CPU-путь как эксперимент) и/или лёгкие CUDA-задачи. До этого — да, JetPack избыточен; фиксируем как техдолг, а не как «фичу».

### 2. tklim: 4 ГБ мало · перегрев SSD в пластике · открытые порты
**RAM — подтверждено live-аудитом:** total 3.9 ГБ, свободно ~520 МБ, доступно 1.5 ГБ, zram-swap уже занят на ~711 МБ. Запас минимальный. → Фаза 2 (оптимизация RAM) обязательна и является предусловием для ML.
**Термика:** SoC холодный (CPU 44 °C, GPU 43 °C). Температуру самого SSD текущие датчики не отдают (smartmontools 6.6 старый), тезис о перегреве корпуса **не проверяем сейчас** → Фаза 4 добавит съём температуры SSD (SMART attr 194) в существующий `nasa-jms583-health`.
**Безопасность (открытые порты → VPN):** справедливо, это противоречит нашему же правилу №4. → Фаза 1, приоритет №1. В репозитории уже есть `TAILSCALE_ACCESS_PLAN.md` — это no-purchase путь.

### 3. dE1l: «Распознавание в Immich отключено, хотя есть NPU»
**Уточнение по железу:** у Jetson **Nano нет DLA/NPU** (он есть у Xavier/Orin) — есть только Maxwell-GPU. Распознавание действительно выключено (ML-контейнера на устройстве нет — подтверждено).
**Ответ:** Включение ML — в плане (Фаза 5), но с оговоркой: официальные CUDA-образы Immich ML собраны под CUDA 11/12, а на Nano CUDA 10.2 (compute 5.3) — GPU-ускорения официальными образами нет. Реальные no-purchase пути ниже.

### 4. falcon4fun: «Immich без ML — деньги на ветер; вынести ML на ПК с GPU (Minix Z150, 16 ГБ)»
**Идея верная, но покупка бокса исключена** условием «на текущем железе».
**Ответ / no-purchase адаптация:** Immich поддерживает удалённый ML-сервер через `IMMICH_MACHINE_LEARNING_URL`. Вместо покупки — направлять ML на **уже имеющийся Windows-ПК** (когда он включён) и обрабатывать бэклог фото пакетно; Nano остаётся хранилищем/сервером. Это тот же приём offload, но без затрат (Фаза 5, Вариант B).

## Дорожная карта (только имеющееся железо, без покупок)

Приоритет: сначала безопасность и стабильность, потом — оживление GPU/ML.

### Фаза 1 — Безопасность (закрыть публичный доступ)
- Увести Nextcloud/Immich/LLM с публичного nginx **за VPN**: Tailscale (см. `TAILSCALE_ACCESS_PLAN.md`) или существующий Amnezia/WireGuard на VPS.
- Оставить наружу только необходимое; добавить fail2ban на VPS, ужесточить nginx (заголовки, rate-limit).
- Заменить self-signed на Let's Encrypt, если появится домен (бесплатно).
- **Итог:** правило №4 CLAUDE.md реально соблюдается.

### Фаза 2 — Оптимизация RAM (предусловие для ML)
- Аудит `mem_limit` всех 13 контейнеров; вынести часть мониторинга (netdata / uptime-kuma / portainer) на VPS или отключить неиспользуемое.
- Тюнинг zram; проверить, что после разгрузки свободно ≥1 ГБ устойчиво.
- **Итог:** появляется бюджет RAM под ML-эксперимент.

### Фаза 3 — Расширение хранилища и бэкап
- Подключить 2 ТБ HDD (уже в наличии), перенести/расширить хранилище.
- restic off-site backup на 2 ТБ HDD и/или на VPS.
- **Итог:** закрыт вопрос ёмкости и оффлайн-копий (комментарий №5 автора).

### Фаза 4 — Мониторинг накопителя (термика фактами)
- Снимать температуру SSD через `smartctl -d sat -a` (attr 194) в рамках `nasa-jms583-health.timer`.
- Telegram-алерт при пороге; логировать тренд.
- **Итог:** тезис о перегреве подтверждается/снимается данными, а не спором.

### Фаза 5 — Оживить GPU/ML (главный запрос читателей), no-purchase
Задача-исследование с чётким критерием выхода. Пробуем по порядку:
- **Вариант A — ML на самом Nano (CPU-путь):** поднять `immich-machine-learning` (aarch64, CPU), только лицевое распознавание, самые лёгкие модели, жёсткий `mem_limit`, запуск по расписанию (ночью). Замерять RAM/термику/стабильность. Годится только если Фаза 2 дала запас.
- **Вариант B — удалённый ML на Windows-ПК:** контейнер `immich-machine-learning` на ПК (CUDA, если есть NVIDIA GPU), `IMMICH_MACHINE_LEARNING_URL` → на ПК; пакетная обработка бэклога, когда ПК включён. Nano не нагружаем.
- **Вариант C — маленькая CUDA-нагрузка под 10.2 на Nano:** если Immich ML не влезает, дать GPU иную осмысленную работу (лёгкая CUDA-задача), чтобы JetPack не простаивал — прямой ответ vvzvlad.
- **Критерий выхода:** если ни A, ни B не укладываются в бюджет RAM/стабильности — **зафиксировать отказ от ML как осознанный trade-off** в README и в статье (это само по себе снимает половину критики).

### Фаза 6 — Оркестратор и развитие API (из ответа автора)
- Довести оркестрацию сервисов и `homecloud_nasa_api` (см. `NAS_Jetson_Nano_API_ROADMAP.md`).
