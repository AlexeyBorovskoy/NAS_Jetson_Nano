## 5. Безопасность

- **Сильные стороны (проверено):** JWT и роли — тест перебирает все маршруты; сервисный токен шлюза сравнивается в постоянное время; атомарная запись журналов; `save_path` шлюза защищён от traversal; хуки aria2 проверяют пути и имена; секретов в истории git не найдено (точечный `git log -p -S`); Portainer только на `127.0.0.1`.
- **Слабые места:** утечка ПДн мимо фильтра на русском (GW-3); SSRF в закачках (API-2/3) — лечится только сетевым барьером для контейнера aria2; `docker.sock` в двух контейнерах с широкими правами (DP-1/2); цепочка поставки (CI-1, DEP-1, DEP-2); проверка секретов в CI не делает того, что обещает (SEC-1); SH-1 — выполнение кода в диагностическом скрипте.

## 6. Архитектура

1. **Один цикл событий на четыре подсистемы** (API, Telegram, Talk, закачки). Любой блокирующий вызов останавливает все четыре (API-1). Супервизор лечит «упал/замолчал», но не «завис синхронно» — это надо записать как ограничение и закрыть переносом I/O в потоки с таймаутом.
2. **Самовосстановление неполное:** внутри процесса — супервизор (есть), сверка журнала с aria2 (есть), между контейнерами — ничего (OPS-1): Docker не поднимает остановленное извне и не реагирует на `unhealthy`.
3. **Расхождение git ↔ устройство** по-прежнему даёт дефекты: захардкоженные пути (SD-2), старые копии скриптов в `/usr/local/sbin` с зашитым адресом VPS (OPS-2).
4. **Шлюз — правильная единая точка выхода в облако**, но учёт бюджета не атомарен (GW-2).

## 9. Отдельный вопрос: медленный VPN на телефоне

Замер через тот же туннель со станции: 33 Мбит/с, задержка до VPS 60–100 мс, 1,0–1,6 с на открытие сайта (TLS через Франкфурт). VPS не загружен. Российские сайты частью режут иностранный IP (`gosuslugi.ru` — таймаут с VPS, `wildberries.ru` — 498). Рекомендация — раздельное туннелирование в приложении AmneziaVPN на телефоне; средства контроля на VPS уже есть (`vnstat`, агент Beszel).

## 10. Неизвестное и блокеры

- Версии зависимостей NAS API, которые реально стоят в образе, — не сверены с базой CVE (нет сети у аудита).
- Эксплуатация API-1 на реальном зависшем ntfs-3g не воспроизводилась (намеренно — это роняет HDD).
- SD-3 (параллельные обходы HDD) — только по коду.
- Причина QA-3 (`tests/unit` не собирается) — гипотеза DeepSeek про подмену `sys.stdout`, не проверена.
- Исправления на устройстве с `sudo` (OPS-1, OPS-2) блокируются классификатором прав агента — выполняет владелец.
