# AmneziaWG 3.1 — шаблон автономной службы для Linux (публичный)

Публичное описание шаблона службы для отдельного Linux-хоста с userspace-демоном
AmneziaWG 3.1.

> **Статус:** шаблон опубликован для проверки и повторного использования. Документ
> описывает сам шаблон, а не инвентаризацию живого хоста. Здесь нет заявления о
> внешней приёмке и нет утверждения о готовности к промышленной эксплуатации.
> Учётных данных, ключей и идентификаторов хоста здесь нет.

## Состав

| Файл | Назначение |
|---|---|
| `awg_material.py` | генерация и развёртывание профилей |
| `awg_control.py` | настройка демона через UAPI и вывод статуса |
| два юнита systemd | демон и отдельный точный NAT |

### `awg_material.py`

- `generate(count, endpoint, port=7843, subnet="10.73.3.0/24")` возвращает
  секретный материал **только в памяти**.
- `provision(root, endpoint)` записывает **23** профиля с правами `0600` и
  отказывается работать, если учётные данные уже существуют.
- Каталог `root` передаёт вызывающая сторона извне этого репозитория; в git
  ничего секретного не попадает.

### `awg_control.py`

- Настраивает UAPI и требует `errno 0` от каждого вызова.
- Проверяет обратное чтение: **23** пира, включённую защиту заголовка (header
  protection), включённые случайные трейлеры (random trailers) и cookies.
- `status` печатает суммарные счётчики, порт и флаги защиты без ключей.

### Юниты systemd

Два юнита намеренно разделены: один запускает демон, второй применяет точно
ограниченный NAT. Поэтому остановка службы снимает ровно эти правила NAT и
ничего больше.

## Фиксированные параметры шаблона

Это константы самого шаблона, а не описание какого-либо конкретного
развёртывания:

- AmneziaWG **3.1**, автономная userspace-служба;
- **23** пира (жёстко);
- UDP-порт **7843**;
- интерфейс **awgse0**;
- адрес сервера **10.73.3.1/24** (подсеть **10.73.3.0/24**);
- WAN-интерфейс **enp0s3**;
- рабочий каталог, принадлежащий root: **/opt/amnezia-awg3-sweden**.

## Предварительные требования

- `python3` с пакетом `cryptography`;
- `iproute2`, `iptables`, `systemd`, поддержка TUN;
- `curl` — только для необязательной ручной проверки;
- файл зависимостей Python: `services/sweden_awg3/requirements.txt`.

## Установка — только вручную

Автоматического установщика нет, и документ намеренно не содержит одной команды,
меняющей хост. Развёртывание требует заранее:

1. аудита целевого хоста;
2. проверки конфликтов по UDP-порту (7843), подсети (10.73.3.0/24) и именам
   интерфейсов;
3. явного согласования сетевых изменений;
4. защищённой резервной копии сгенерированных профилей.

## Запуск службы

Запуск основной службы добавляет точные правила NAT; отдельный NAT-юнит снимает
ровно эти правила при остановке.

Следующее остаётся отдельными явными согласованиями и **не** устанавливается
автоматически:

- входящее правило UDP в UFW;
- маршрут на выход (egress);
- постоянная настройка `ip_forward`.

## Тесты

```bash
python -m unittest discover -s tests/sweden_awg3 -v
```

`accept_clients.py` — **необязательный** интеграционный тест, запускаемый от
root. Ему нужны:

- явная переменная окружения `AWG_ENDPOINT` с IPv4-адресом;
- фиксированный каталог из 23 конфигураций;
- временный сетевой namespace `awgst`, пара `veth` в `10.203.31.0/30` и локальные
  клиенты VPN, DNS `1.1.1.1` и HTTPS `api.ipify.org`.

Тест не меняет правила файрвола, но **создаёт** временные маршруты и интерфейсы
на хосте, поэтому требует согласованного окна обслуживания и никогда не
запускается в CI.

## Границы доказанного

Синтетический тест на одном хосте **не доказывает**:

- доступность из мобильных сетей операторов;
- отсутствие утечек IPv6;
- поведение после перезагрузки;
- работу при одновременной нагрузке всех 23 клиентов.

Это открытые пункты для будущей приёмки, а не заявления данного шаблона.

## Откат (вручную)

1. `systemctl disable --now amnezia-awg3-sweden.service` — NAT-юнит снимает своё
   точное правило при остановке.
2. Удалить только новые правила UFW и новый файл sysctl, предварительно проверив
   зависимости.

Никогда не очищать файрвол целиком и не отключать форвардинг вслепую. Сохранять
закрытую резервную копию профилей и прежний VPN до проверки новой службы.
