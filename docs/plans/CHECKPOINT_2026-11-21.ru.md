# Точка 2026-11-21: Codex на VPS — рабочие контуры

[English](CHECKPOINT_2026-11-21.md), [предыдущая точка](CHECKPOINT_2026-11-20_CODEX_VPS_PILOT.ru.md)

Пилот 2026-11-20 закончился NO-GO, потому что песочница не запускалась. Разбор доведён до конца, блокер снят адресно, и на том же хосте развёрнуты три рабочих контура Codex CLI. Входы выполнены, задачи реально правят файлы, VS Code подключён к серверу с обоих контуров.

## Что сделано

**Пользователи и изоляция.** `dev-personal` (личный), `dev-work` (рабочий), `nil` (гостевой). Дома `700`, свои `~/projects`, свой `CODEX_HOME`, свой `auth.json` (`600`). Ни у одного нет `sudo` и доступа к Docker: `sudo -n true` требует пароль, `/var/run/docker.sock` отсутствует. Проверено, что чужой домашний каталог, чужой `auth.json` и `/root` недоступны.

**Песочница.** Блокер пилота — `kernel.apparmor_restrict_unprivileged_userns=1` и bwrap без привязанного профиля. Снят адресным AppArmor-профилем `/etc/apparmor.d/codex-dev-bwrap` на точный путь бинарника; глобальных послаблений нет, `danger-full-access` не разрешён. Профиль синтетического пилота сохранён без изменений, добавлены `dev-personal-ws`, `dev-work-ws`, `nil-ws` — запись только в `~/projects`, сеть включена, чтение чужих `.ssh` и `auth.json` запрещено.

**Две ошибки, которые стоили времени.** `codex sandbox` отвечал «Permission denied (os error 13)», потому что Codex наследовал рабочий каталог `/root` и делал `chdir`; запускать только из каталога проекта. И `default_permissions` в `/etc/codex/requirements.toml` обязан входить в `allowed_permission_profiles` — иначе старт падает до выполнения команды.

**Вход.** OpenAI не обслуживает российские адреса (`unsupported_country_region_territory`), поэтому браузер для входа ходит через сам VPS (SOCKS), а возврат идёт на `127.0.0.1:1455` через `ssh -L`, минуя прокси. `codex login` держится только отсоединённым юнитом `systemd-run` — в ssh-сессии он умирает вместе с каналом (две неудачные попытки). Оба рабочих контура: `Logged in using ChatGPT`.

**Проверено задачами, не статусами.** В `dev-personal` и `dev-work` команда `codex exec` изменила `main.py` (sha256 `a55c14…` → `0f6c16…`); в `nil` дописала строку в `NOTES.md`, `git status` → `M NOTES.md`, 28 847 токенов.

**VS Code.** Remote-SSH поставлен из VSIX (маркетплейс недоступен по DNS) и требует двух настроек: `remote.SSH.path` на клиент Git ssh и `remote.SSH.remotePlatform = linux` для каждого профиля. Без второй VS Code спрашивает платформу, и выбор «Windows» даёт `bash: line 1: powershell: command not found`. Открыты окна `demo [SSH: VPS-Personal-socks]` и `demo [SSH: VPS-Work-socks]`.

**Git.** Всё под аккаунтом владельца: приватные репозитории `codex-vps-test-personal`, `codex-vps-test-work`, `codex-vps-test-son`. Доступ — deploy-ключами на конкретный репозиторий (`read-write`), ключ на весь аккаунт на сервер не выкладывался. Идентичности раздельные; коммиты `c232cd93`, `87b4525f`, `0ceb397`, `82bb18b` дошли до GitHub.

**Гостевой контур.** Ключ и документация передаются папкой `nil/` в корне проекта — она в `.gitignore` (`/nil/`), приватный ключ в git не попадает. Отдельная идентификация Codex не требуется: в `~/.codex/auth.json` контура положена копия уже выполненного входа; ограничение — при рассинхронизации токенов вход повторяется.

## Сетевая оговорка

Новые SSH-подключения с домашней сети режутся на обмене баннерами (тот же дефект, что в отчёте D2), при этом уже установленный туннель работает. Рабочий обход — профили `VPS-*-socks` с `ProxyCommand connect -S 127.0.0.1:1080`, требует живого `ssh -N -D 1080 aeza-sweden`. Это же спасло развёртывание, когда прямой канал отваливался на девять попыток подряд.
