1. Рекомендуемый стек

Для Windows я бы взял:

Уровень	Компонент	Назначение
Чат	Telegram / ваш существующий бот	интерфейс пользователя
Agent	локальный LLM / Claude / GigaChat	понимание команды
Протокол	MCP	управление инструментами
Оркестратор изображений	ComfyUI	выполнение AI-workflow
Основной редактор	Qwen-Image-Edit	интеллектуальное редактирование
Альтернатива	FLUX.1 Kontext	сложное редактирование
Апскейл	Real-ESRGAN	увеличение разрешения
Background	BiRefNet	удаление/выделение фона
Базовая обработка	OpenCV + Pillow	цвет, размер, EXIF, JPEG
Хранилище	локальная файловая система	исходники/результаты
Очередь	Redis, позднее	очередь тяжёлых задач

Главный элемент здесь — ComfyUI. Он выступает не как GUI для пользователя, а как движок выполнения графа обработки.

2. Основная модель — Qwen-Image-Edit

Я бы сейчас начал именно с Qwen-Image-Edit, а не с Kandinsky.

Qwen-Image — открытая модель класса 20B, а семейство Qwen-Image-Edit предназначено именно для редактирования существующих изображений. В документации заявлены, в частности, удаление/добавление объектов, изменение стиля, улучшение деталей и работа с позой.

Особенно важно для вашего сценария:

модель должна изменять существующую фотографию, а не генерировать новую фотографию по описанию.

Например:

Исходная фотография
        │
        ▼
Qwen-Image-Edit
        │
        ├── "убери людей справа"
        ├── "сделай небо более выразительным"
        ├── "сделай цвет естественнее"
        ├── "сделай фотографию в стиле travel magazine"
        └── "сделай мягкую glamour-ретушь лица"

При этом Qwen отдельно указывает на сохранение визуальной семантики исходного изображения при редактировании.

3. Я бы сделал MCP не слишком «умным»

Это принципиальный момент.

Не надо давать LLM один инструмент:

edit_image(prompt)

Лучше сделать специализированный API:

photo_analyze()
photo_enhance()
photo_retouch()
photo_remove_object()
photo_remove_background()
photo_replace_background()
photo_color_grade()
photo_upscale()
photo_edit()
photo_compare()

Тогда Agent сможет сам выбрать технологию.

Например пользователь пишет:

Удали мусорный контейнер справа и сделай фотографию немного светлее.

Agent:

photo_analyze
       ↓
photo_remove_object
       ↓
photo_enhance
       ↓
photo_compare

А если:

Сделай из этого нормальную фотографию с экскурсии.

Тогда:

photo_analyze
       ↓
photo_enhance
       ↓
photo_upscale
4. Самое интересное — photo_analyze

Я бы обязательно сделал этот инструмент.

LLM получает фотографию и сначала определяет:

{
  "type": "travel_photo",
  "people": 3,
  "faces": 2,
  "architecture": true,
  "sky": true,
  "low_light": true,
  "blur": false,
  "noise": "medium",
  "composition": "good"
}

После этого Agent уже выбирает pipeline.

Например:

Экскурсионная фотография
photo_analyze
       │
       ├── architecture = true
       ├── sky = true
       ├── people = 3
       └── low_light = true
              │
              ▼
       Travel workflow
              │
       ┌──────┼──────┐
       ▼      ▼      ▼
     color   light  denoise
       │      │      │
       └──────┼──────┘
              ▼
          Real-ESRGAN
5. Для портретов отдельный workflow

Я бы не заставлял Qwen делать всю beauty-ретушь.

Лучше:

                     portrait
                        │
                        ▼
                  face detection
                        │
             ┌──────────┴──────────┐
             ▼                     ▼
       skin retouch            face/light
             │                     │
             └──────────┬──────────┘
                        ▼
                  Qwen-Image-Edit
                        │
                        ▼
                   Real-ESRGAN

Так вы сможете контролировать интенсивность.

Например MCP:

photo_retouch(
    style="glamour",
    skin=0.35,
    eyes=0.20,
    teeth=0.15,
    face_shape=0.05,
    makeup=0.10
)

То есть не превращать человека в другого человека.

6. Для обычных фотографий я бы вообще не использовал генеративную модель постоянно

Это очень важно.

Если пользователь пишет:

Сделай фотографию ярче и убери шум.

Нет смысла запускать 20B diffusion model.

Лучше:

OpenCV
Pillow
Real-ESRGAN

А генеративную модель использовать только там, где действительно требуется семантическое изменение.

Получается:

                  MCP
                   │
                   ▼
             photo_analyze
                   │
        ┌──────────┼───────────┐
        ▼          ▼           ▼
    обычная      портрет     изменение
    обработка                 объекта
        │          │           │
        ▼          ▼           ▼
   OpenCV       Retouch     Qwen Edit
   Pillow                    / Flux
        │          │           │
        └──────────┼───────────┘
                   ▼
              Real-ESRGAN

Это будет намного быстрее и экономичнее по GPU.

7. Real-ESRGAN обязательно

Для финального этапа я бы поставил Real-ESRGAN.

Он предназначен именно для восстановления/увеличения изображений; поддерживает произвольный масштаб, тайлинг и отдельное улучшение лиц через GFPGAN.

Например:

Telegram photo
     ↓
2048 × 1365
     ↓
AI processing
     ↓
2048 × 1365
     ↓
Real-ESRGAN
     ↓
4096 × 2730

Но я бы не делал 4× всегда. Для фотографий обычно разумнее дать Agent выбор:

upscale = 1.5
upscale = 2
upscale = 4
8. BiRefNet

Для фона я бы добавил BiRefNet.

Он хорошо подходит для:

вырезания человека;
удаления/замены фона;
подготовки маски;
дальнейшего inpainting.

Есть локальные реализации BiRefNet, которые работают без отправки изображений во внешнее хранилище.

Тогда можно сделать:

Замени фон на красивый вечерний Париж.

Pipeline:

original
   │
   ▼
BiRefNet
   │
   ├── foreground
   └── mask
          │
          ▼
   Qwen-Image-Edit
          │
          ▼
      composite
9. А FLUX куда?

FLUX.1 Kontext я бы оставил вторым генеративным движком.

Он специально ориентирован на image editing и позволяет передавать исходную фотографию вместе с текстовой инструкцией. Открытая FLUX.1 Kontext [dev] существует, но имеет Non-Commercial License, поэтому для корпоративного продукта обязательно надо отдельно проверить лицензионные ограничения.

Поэтому для вашего проекта:

Qwen-Image-Edit — основной кандидат.

FLUX Kontext — дополнительный экспериментальный backend.

И MCP вообще не должен знать, какая модель работает:

photo_edit()
      │
      ▼
Image Engine
      │
      ├── qwen
      ├── flux
      └── future_model

12. Где всё это запускать

С учётом вашей архитектуры я бы не ставил всё в Telegram-сервер.

Лучше:

                    Telegram
                       │
                       ▼
                MCP / Agent
                       │
              ┌────────┴────────┐
              │                 │
              ▼                 ▼
          Text LLM          Photo MCP
                                │
                         HTTP / local
                                │
                                ▼
                            ComfyUI
                                │
                    ┌───────────┼───────────┐
                    ▼           ▼           ▼
                  Qwen        BiRefNet   RealESRGAN
                    │
                    ▼
                 output
                    │
                    ▼
                 Telegram

Это очень хорошо ложится на вашу существующую идею MCP + Telegram + локальные LLM.

13. Но есть один серьёзный вопрос — ваше железо

Здесь я бы пока не начинал установку Qwen-Image-Edit вслепую.

Qwen-Image-Edit — тяжёлая модель. Ваш ноутбук с 32 ГБ RAM и мобильной GPU, насколько я понимаю, не является хорошей машиной для комфортного запуска такой модели. В результате можно получить либо очень медленную обработку, либо необходимость агрессивной квантизации/offload.

Поэтому я бы разделил систему:

             Telegram
                 │
                 ▼
              MCP
                 │
        ┌────────┴────────┐
        │                 │
        ▼                 ▼
     CPU/GPU           GPU Server
   простая обработка   генеративный AI
        │                 │
        ▼                 ▼
 OpenCV/Pillow       Qwen-Image-Edit
 Real-ESRGAN         FLUX Kontext
                     BiRefNet

То есть обычная обработка работает на вашем компьютере, а тяжёлые модели можно вынести на отдельную GPU-машину.

Мой итоговый выбор

MVP:

MCP Server: Python
API: FastAPI
Workflow engine: ComfyUI
Основная AI-модель: Qwen-Image-Edit
Object removal / semantic editing: Qwen-Image-Edit
Background: BiRefNet
Upscale: Real-ESRGAN
Базовая обработка: OpenCV + Pillow
Хранилище: локальная папка или MinIO
Очередь: сначала без Redis, затем Redis
Интерфейс: ваш Telegram-бот
LLM: тот же Agent, который сейчас управляет вашим MCP
Все фотографии: по умолчанию локально
Облачные API: только как резервный backend.

Это даст вам не «бота для генерации картинок», а универсальный MCP Photo Service, который впоследствии можно подключить не только к Telegram, но и к Cursor, Claude Code, веб-интерфейсу и вашей корпоративной платформе.

И отдельно: Qwen-Image-Edit уже сейчас выглядит более подходящим фундаментом для вашей задачи, чем Kandinsky, поскольку задача у вас именно редактирование существующих фотографий через естественный язык, а не генерация картинки с нуля.
