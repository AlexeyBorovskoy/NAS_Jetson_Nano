## Продолжение: стабильная цель SMART — код готов, установка ожидает sudo

Проверено: недельный самотест и `check_hdd_smart` в Talk-мониторе использовали
нестабильный буквенный путь `/dev/sdb`.
Подготовлены исправления:

- Юнит требует `/etc/nas-smart-hdd.env` с `NAS_SMART_HDD_DEVICE`, проверяет наличие
  блочного устройства перед запуском smartctl. В локальной конфигурации должна
  быть ссылка `/dev/disk/by-id/...` на весь HDD, без `-partN`.
- Монитор читает ту же настройку, отклоняет буквенные пути и разделы без вызова
  smartctl; запасного `/dev/sdX` нет. Отсутствие настройки даёт предупреждение.
- Реальные идентификаторы хранятся только на Jetson; в git не добавлены.

Проверки: 8 новых unittest/pytest-проверок, 5 существующих проверок парсера
SMART-самотеста, 8 проверок systemd 237 и 2 проверки запуска unit-тестов;
храповик метрик проходит без исключений. Ведущий выделил проверку
формата пути в небольшую функцию, чтобы не увеличивать максимальную сложность
существующего монитора. Окончательный пакет проверен на Python 3.6 хоста, хеши
совпали; стабильная ссылка действительно указывает на родительский диск
смонтированного NTFS-архива. `systemd-analyze verify` от непривилегированного
пользователя отказал из-за cgroup; проверка включена в root-шаг **до записи**.

На Jetson подготовлено:
`/home/admin/nasa/.agent-work/tmp/smart-stable-20261019/`.

```sh
# Без записи и без запуска самотеста:
python3 /home/admin/nasa/.agent-work/tmp/smart-stable-20261019/install.py --check
# Установка после получения рабочего sudo:

```

Установщик сверяет текущую точку архива со стабильным идентификатором целого
диска, проверяет пакет, сохраняет прежние юнит, монитор и конфигурацию в
`.agent-work/archives/smart-stable-20261019/`, устанавливает файлы атомарно и
выполняет `daemon-reload`. Расписание не меняется, самотест не запускается.
Откат после установки: вернуть `unit.before.service` и `monitor.before.py` на
прежние пути, прежний конфиг — только если он существовал; иначе убрать только
