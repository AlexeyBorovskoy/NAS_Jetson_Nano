## 1. Статус и правила

- Выкат выполняет **только ведущий** (правило №16): VPS — критичная зона, ни субагент, ни
  исполнитель DeepSeek эту задачу не берут.
- Команды в шагах приведены **для будущего выката с явного разрешения владельца**; сам
  этот документ разрешением не является.
- Перед началом и после завершения — снимки правила №13 (до/после, команда в шаге 2).
- Ничего необратимого: runbook не удаляет данные. Полное удаление учёта (юниты, код,
  каталоги) в него не входит — см. §8.
- Любая команда на VPS выполняется через helper `vps` ниже с ограничением памяти
  (правило владельца 2026-10-08): `MemoryMax=256M`, `MemorySwapMax=0`.
  04.10 наша же диагностика прочитала весь журнал sshd в переменную оболочки и задушила VPN
  нехваткой памяти (CLAUDE.md, «Грабли»). Журнал — только потоком и с `--since`, не в переменную.

## 2. Что делает выкат

Ставит на VPS учёт нагрузки — **только наблюдение**, без ограничений скорости и блокировок:

- `nasa-vpnmon-collect.timer` — раз в 60 с снимает счётчики пиров `awg0` и метрики хоста
  (только чтение) в SQLite `/var/lib/nasa-vpnmon/vpnmon.db`;
- `nasa-vpnmon-report.timer` — в 10:00 МСК отправляет владельцу в Telegram суточную сводку;
  таймер включается установщиком только при наличии `/etc/nasa-vpnmon/telegram.env`.

Не трогаются: контейнеры и конфиги Amnezia, ufw, iptables, маршруты, sshd, nginx, Docker.
Новых портов, пакетов и пользователей нет; наружу ничего не открывается (спецификация §9).

### Команды VPS с ограничением памяти

Перед любым шагом определить helper в локальной сессии Git Bash. Login shell на VPS
должен быть Bash для совместимости с quoting `%q`. Helper принимает одну строку команды
и сохраняет stdin для tar, here-documents и конвейера учётных данных. Весь удалённый
shell/конвейер работает в ограниченном scope; прямым SSH на VPS helper не обходить.
Если scope или ограничения памяти не создаются — стоп, без повторения без ограничений.
Службы монитора systemd сохраняют отдельные лимиты своих юнитов.

```bash
VPS_HOST=95.163.176.103
VPS_HOST_KEY_ALIAS=95.163.176.103
vps() {
  [ "$#" -eq 1 ] || { printf '%s\n' 'vps: exactly one command argument required' >&2; return 2; }
  local program
  printf -v program '%q' "$1"
  ssh -o BatchMode=yes -o StrictHostKeyChecking=yes -o ConnectTimeout=8 \
    -o ServerAliveInterval=15 -o ServerAliveCountMax=2 \
    -o "HostKeyAlias=$VPS_HOST_KEY_ALIAS" -i ~/.ssh/borovskoy_new_ed25519 \
    "root@$VPS_HOST" \
    "systemd-run --quiet --scope -p MemoryMax=256M -p MemorySwapMax=0 bash -c $program"
}
```

## 7. Риски и приватность

- 🔴 **Телеметрия содержит имена пиров и публичные ключи.** БД `/var/lib/nasa-vpnmon/vpnmon.db`,
  файл `/etc/nasa-vpnmon/names.conf`, вывод `collect.py --dry-run` и таблица отчёта содержат
  имена людей и префиксы их ключей. Правила: не выводить реальные идентификаторы в stdout
  дольше необходимого; не копировать их в чаты, коммиты, документы и карточки задач;
  диагностику делать по счётчикам (как в шаге 8), а не выгрузкой содержимого БД.
- **Токен.** `/etc/nasa-vpnmon/telegram.env` — root, 0600; шаг 6 переносит его конвейером
  без вывода значения. Проверять права — `ls -l`, не `cat`.
- **Правило №13.** До и после выката: `amnezia-*` не перезапускались, число пиров не
  уменьшилось, наружу слушают только прежние порты. Любое расхождение — стоп и откат.
- **Только наблюдение.** Ограничений скорости и блокировок нет; сборщик вызывает `docker`
  только с `exec` (постоянный скрипт чтения) и `inspect`; `dump`/`showconf` запрещены и
  проверяются тестом (§8 спецификации).
- **Недоступность `amnezia-awg2`** не искажает учёт: событие `awg_unavailable` фиксирует
  переход состояния; каждый недоступный замер увеличивает почасовой счётчик `awg_miss`.
  Метрики хоста продолжают писаться, пиры не помечаются удалёнными.
- **Секретов в git нет:** в репозиторий попадают только `names.conf.example` и
  `telegram.env.example` без значений.
- Отчёт уходит только в личный чат владельца; семье объявление не требуется (шаг 11).

## 8. Безопасный откат

Откат **останавливает только таймеры** учёта. Данные и конфигурация сохраняются: часовые
ряды и события — в `/var/lib/nasa-vpnmon/vpnmon.db`, имена — в `/etc/nasa-vpnmon/names.conf`.
Ничего не удаляется: ни БД, ни конфиг, ни код, ни юниты. VPN не задет.

```bash
vps 'systemctl disable --now nasa-vpnmon-collect.timer nasa-vpnmon-report.timer; systemctl stop nasa-vpnmon-collect.service nasa-vpnmon-report.service; systemctl list-timers --all "nasa-vpnmon-*" --no-pager; bash /root/vpnmon-src/vpn_monitor/rule13_snapshot.sh | diff /root/vpnmon-rule13-before.txt - && echo "правило 13: без изменений"'
```
Ожидание: таймеры выключены, `правило 13: без изменений`.
