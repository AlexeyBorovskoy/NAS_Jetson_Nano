# Голосовые сообщения `@бобик` (E10) — спецификация

> 🇷🇺 Русский · 🇬🇧 [English summary](#english-summary)
> **Дата:** 2026-09-20 · **Статус:** утверждена владельцем · **Этап плана:** E10
> **Основание:** бейк-офф на целевом железе — `docs/research/VOICE_BENCHMARK_JETSON_2026-09-20.md`

## 1. Зачем

Семья пишет боту текстом. Голосовое сообщение быстрее и удобнее, особенно с телефона на ходу
и для тех, кому печатать тяжело. Задача — принимать голосовые так, чтобы для остальной системы
они ничем не отличались от текста.

## 2. Движок: Vosk small-ru (решение владельца 2026-09-20)

Замеры на самом Jetson, не на эмуляции (полные числа — в документе бейк-оффа):

| Показатель | Vosk small-ru | whisper.cpp tiny |
|---|---|---|
| RTF (доля реального времени) | 0.35–1.25 | 1.38–9.95 |
| WER, 15 фраз Golos farfield | **17.07 %** | 62.20 % |
| Модель на диске | 46.2 МБ (88 МБ развёрнутая) | 77.7 МБ |
| Пик памяти | 244.8 МБ (резидентная модель) | 178.0 МБ (перезагрузка на вызов) |

Конвертация OGG/Opus → WAV 16 кГц моно — **`opus-tools`**, не `ffmpeg`: в 9 раз меньше места
под зависимости (3.8 МБ против 34.8 МБ) и в 4.7 раза быстрее на батче.

⚠️ **Ловушка установки:** с Jetson недостижимы `alphacephei.com` и апекс `github.com`
(TLS-таймаут на HTTP и HTTPS), при этом их CDN-поддомены и HuggingFace работают. Установка
«по официальной инструкции» молча встанет. Модель берётся с зеркала, контрольная сумма
сверяется с документированной.

## 3. Архитектура: распознавание — отдельный контейнер

Новый контейнер `homecloud_stt`: Vosk + модель + `opus-tools`, HTTP-обработчик принимает
аудио и возвращает текст. NAS API обращается к нему по сети Docker.

**Почему не процессом внутри API.** У `homecloud_nasa_api` `mem_limit` 128 МБ, Vosk в пике
берёт 245 МБ. Поднять лимит API — значит поселить распознавание рядом с Telegram-ботом и
качалкой: превышение памяти утащит всё разом. Отдельный контейнер имеет свой лимит
(предложено 320 МБ) и свой отказ: умер распознаватель — бот отвечает «не разобрал»,
а не падает вместе с ним.

**Таймаут вызывающей стороны строго больше, чем у вызываемой** (записанное правило проекта):
API ждёт распознавание дольше, чем контейнер сам себя ограничивает.

## 4. Поток обработки

1. Приходит `message.voice` (в группе или в личке).
2. Проверка длительности: `duration > 60 с` → отказ, дальше ничего не делается.
3. `getFile` → скачивание OGG/Opus.
4. Конвертация `opus-tools` → WAV 16 кГц моно.
5. Распознавание в `homecloud_stt` → текст.
6. **Текст подставляется на место текста сообщения** и идёт обычным путём:
   `addressed_text()` ищет «бобик», `route()` разбирает команду.

Ключевое: правила обращения и разбор команд **не дублируются**. Голос — приставка на входе.

## 5. Обращение в группе: слушать всё, отвечать на «бобик» (решение владельца)

В группе «Боровские» распознаётся **каждое** голосовое, потому что узнать об обращении
можно только после распознавания. В личке, как и сейчас, любое сообщение — обращение.

**Жёсткое следствие для приватности.** Если в распознанном тексте нет «бобика»:
- текст **не пишется** никуда: ни в журнал, ни в память диалога, ни в ответ;
- остаётся только счётчик обработанных сообщений (без содержимого);
- наружу не уходит ничего.

Звук не покидает дом ни при каком раскладе: Vosk работает на Jetson. Наружу, в GigaChat,
может уйти только адресованный боту вопрос — через существующее редактирование
персональных данных, как и для текста.

## 6. Ограничения

| Ограничение | Значение | Почему |
|---|---|---|
| Длительность голосового | **60 секунд** | При RTF ≈1 это минута процессора на сообщение; длинное голосовое заблокирует очередь остальным |
| Одновременных распознаваний | **1** | Прямой вывод из инцидента 2026-09-20: два тяжёлых процесса на двух ядрах кладут не себя, а систему целиком |
| Команда «скачай» голосом | **не выполняется** | Ссылку и magnet голосом не продиктуешь, ошибка распознавания в адресе = закачка не того. Бот просит прислать ссылку текстом |

Голосом остаются вопросы, «закачки», «отмени», «забудь», «что сломалось» — там ошибка
в слове не приводит к необратимому действию.

## 7. Ответ бота

Бот начинает ответ с того, что услышал: **«Расслышал: …»** — и дальше обычный ответ.
Человек сразу видит, если его поняли неверно, вместо того чтобы гадать, почему ответ странный.
Решение владельца 2026-09-20.

## 8. Отказы и деградация

| Случай | Поведение |
|---|---|
| Голосовое длиннее 60 с | Отказ с просьбой написать текстом; файл не скачивается |
| Контейнер распознавания недоступен | «Не разобрал, напишите текстом»; бот продолжает работать с текстом |
| Очередь занята | Ждёт своей очереди; при длительном ожидании — честный отказ, а не молчание |
| Распознан пустой текст | Отказ; в память диалога ничего не пишется |
| Распознано «скачай …» | Просьба прислать ссылку текстом; закачка не запускается |

Тишина ≠ успех (правило проекта): каждый отказ виден человеку.

## 9. Что обязаны проверять тесты

1. Голосовое в группе без «бобика» — бот молчит **и** ничего не сохраняет (проверять именно
   отсутствие записи, а не только отсутствие ответа).
2. Голосовое длиннее 60 с — отказ, скачивания файла не происходит.
3. Распознанное «скачай <что-то>» — закачка **не** создаётся.
4. Недоступный контейнер распознавания — бот отвечает, а не виснет.
5. Второе голосовое при занятой очереди — не запускает параллельное распознавание.
6. Ответ содержит «Расслышал: …» с распознанным текстом.

## 10. Риски и непроверенное

- **Качество на живых голосах семьи не измерено.** В бейк-оффе целевые фразы были
  синтезированы `espeak-ng` (роботический голос) — это слабый сигнал. Настоящая проверка
  только в бою, на голосах Ольги, Ивана, Ульяны, Анны.
- **Память Jetson.** 245 МБ резидентно при 14 контейнерах и ~1.7 ГБ доступных — запас есть,
  но не измерен под одновременной нагрузкой (закачка + Immich + распознавание).
- **Шум и дальняя речь.** WER 17 % получен на наборе farfield; в реальной кухне с телевизором
  будет хуже, насколько — неизвестно.
- **Приватность при выборе «слушать всё»** зависит от дисциплины кода: правило «нет бобика —
  ничего не сохраняем» должно быть закрыто тестом, иначе однажды утечёт в журнал.

### English summary

Voice messages for the family bot `@бобик`, stage E10. Engine chosen by the owner on device
benchmarks: **Vosk small-ru** (RTF 0.35–1.25 and WER 17.07 % versus whisper.cpp tiny's
1.38–9.95 and 62.20 %); OGG/Opus is converted with `opus-tools`, which beats `ffmpeg` 9× on
disk and 4.7× on speed. Recognition lives in its own container (`homecloud_stt`), because the
API container is capped at 128 MB while Vosk peaks at 245 MB; if the recogniser dies the bot
still answers. Recognised text is substituted for the message text and follows the **same**
path as typed text, so addressing rules and command parsing are never duplicated.

In the family group every voice message is transcribed — the bot cannot know it was addressed
until it has the text. Therefore: if the transcript contains no "бобик", it is stored nowhere
(no log, no dialogue memory, no reply), only a counter remains. Audio never leaves the house.
Limits: **60 seconds** per message, **one** recognition at a time (the 2026-09-20 hang proved
that two heavy readers take down the whole system), and the "download" command is **not**
executed from voice — a URL cannot be dictated and a misheard address downloads the wrong
thing. Every reply opens with "Расслышал: …" so a misunderstanding is visible immediately.

Unverified risks: quality on the family's real voices (benchmark phrases were synthesised),
memory behaviour under simultaneous load, and noisy far-field speech.
