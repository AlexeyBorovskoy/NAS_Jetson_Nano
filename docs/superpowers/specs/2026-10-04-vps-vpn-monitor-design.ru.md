# Учёт нагрузки VPS и трафика пользователей VPN — спецификация

> **Дата:** 2026-10-04 · **Статус:** утверждена владельцем 2026-10-04 целиком
> **Основание:** запрос владельца 04.10 («сводная информация по нагрузке VPS и сетевой активности
> каждого пользователя»), промт `claude_amnezia_vps_monitoring_prompt.md` (вне git), аудит VPS
> только на чтение 2026-10-04 16:38 UTC.
> Английская пара — `2026-10-04-vps-vpn-monitor-design.md`.

## 1. Зачем

Владелец раз в сутки получает в личный Telegram сводку: как жил VPS (CPU, память, диск, сеть,
простои) и сколько трафика прошло через VPN у каждого пользователя за сутки, 7 и 30 дней,
кто сейчас в сети и кто давно молчит. Только наблюдение: ни ограничений скорости, ни блокировок.

## 2. Решения владельца (2026-10-04)

| Вопрос | Решение |
|---|---|
| Где смотреть | **Только Telegram, отчёт раз в сутки.** Веб-панели, Grafana, отчёта по запросу и тревог в реальном времени нет |
| Кто отправляет | **Вариант B — VPS отправляет сам**, независимо от Jetson. На VPS появляется постоянный файл с токеном бота |
| Устройство и учёт | Части 1–2 ниже утверждены в чате: «план принимается» |

Отвергнуто с причиной: стек Prometheus + Grafana + cAdvisor + node_exporter из промта. На VPS с
1 vCPU и 1.9 ГБ без swap он занял бы, по оценке (не замер), 350–500 МБ, дублирует Beszel и не нужен
для одного текстового сообщения в сутки. Вариант C (Prometheus без Grafana) — 150–250 МБ ради того же.

## 3. Исходное состояние (замер 2026-10-04 16:38 UTC, только чтение)

- VPS: Ubuntu 24.04.4, ядро 6.8, KVM (Aeza), **1 vCPU, 1967 МБ RAM, swap нет**, диск 30 ГБ (27 %),
  часовой пояс `Etc/UTC`, Python 3 есть, Docker 29.1.3. Нагрузка почти нулевая (id 92–98 %).
- `amnezia-awg2`: интерфейс `awg0`, подсеть `10.8.1.0/24`, UDP 40568, **21 пир**; внутри контейнера
  есть `wg` и `awg`; `clientsTable` даёт имя для 15 пиров. Шесть безымянных — ручные пиры 25.08:
  `.17` (Vostro) и `.18–.22` (запасные).
- `amnezia-xray`: VLESS/Reality на 443, 11 клиентов. **В конфиге нет `stats`, `api`, `policy`, у
  клиентов нет `email`** → учёт по пользователям xray невозможен без правки конфига и перезапуска.
  За 11 ч через контейнер прошло ~18 МБ против ~24 ГБ через `awg0`.
- Контейнеры Amnezia: `privileged`, `LogDriver=none`, сеть `bridge`.
- Мониторинг уже есть: Beszel hub (:8091) и агент VPS (:45877) — снимок хоста и контейнеров.
- Счётчики WireGuard живут в памяти ядра и обнуляются при перезапуске контейнера или VPS.
- **2026-10-04 04:55:49–05:27:38 UTC VPS был выключен гипервизором** (`qemu-ga: guest-shutdown`,
  `hypervisor initiated shutdown`): VPN лежал 32 мин. Инициатор (панель владельца или работы
  провайдера) этими данными не различается.

## 4. Границы

Не делаем: учёт по пользователям xray (только общий трафик контейнера); число соединений и
адресаты по клиенту (conntrack в namespace контейнера не читается, и это вопрос приватности);
веб-интерфейс; тревоги в реальном времени; любые ограничения трафика.
Не трогаем: контейнеры и конфиги Amnezia, firewall, маршруты, sshd, Docker. Новых портов нет.

## 5. Устройство (часть 1, утверждена)

```
VPS
├─ nasa-vpnmon-collect.timer   каждые 60 с → /usr/local/lib/nasa-vpnmon/collect.py  (root)
│     лимиты юнита: CPUQuota=20 %, MemoryMax=64M, Nice=10, TimeoutStartSec=30
│     ├─ docker exec amnezia-awg2 <постоянный скрипт чтения>   — один exec на запуск
│     ├─ docker inspect amnezia-awg2 / amnezia-xray            — StartedAt, RestartCount, Pid
│     ├─ /proc/<pid awg2>/net/dev                              — счётчики awg0, без exec
│     ├─ /proc/<pid xray>/net/dev                              — трафик контейнера xray, без exec
│     ├─ /proc/stat, /proc/meminfo, /proc/loadavg, statvfs("/"),
│     │  /proc/net/dev (WAN), nf_conntrack_count, /proc/sys/kernel/random/boot_id
│     └─ SQLite /var/lib/nasa-vpnmon/vpnmon.db  (0600, WAL)
└─ nasa-vpnmon-report.timer    10:00 Europe/Moscow, Persistent=true
      → /usr/local/lib/nasa-vpnmon/report.py → Telegram sendMessage владельцу
        юнит: TimeoutStartSec=300 (> 3 попыток × 10 с + паузы 30/60 с = 120 с)
        токен и chat_id: /etc/nasa-vpnmon/telegram.env (root, 0600)
        имена безымянных пиров: /etc/nasa-vpnmon/names.conf (root, 0600, вне git)
```

Код — `services/vpn_monitor/` (`collect.py`, `report.py`, общий модуль хранения, `install_vps.sh`,
юниты), тесты — `tests/vpn_monitor/`. Только стандартная библиотека Python 3.12 (`sqlite3`,
`urllib`); `apt`/`pip` не нужны. Время Москвы — фиксированный сдвиг UTC+3 (летнего времени нет
с 2014 г.); `zoneinfo` не используется — на Windows в тестах у него нет базы поясов.

**Постоянный скрипт чтения внутри `amnezia-awg2`** — строка-константа в коде, без подстановок:
`set -e; wg show awg0 allowed-ips; echo @@; wg show awg0 transfer; echo @@; wg show awg0 latest-handshakes;
echo @@; cat /opt/amnezia/awg/clientsTable 2>/dev/null || true`. `set -e`: сбой `wg` — это «awg2
недоступен», а не «ноль пиров» (иначе все пиры были бы помечены удалёнными). 🔴 Запрещены `wg show … dump` (печатает preshared-ключи)
и `wg showconf` (печатает приватный ключ) — это проверяется тестом по исходнику.

## 6. Учёт (часть 2, утверждена)

- **Разница с прошлым замером.** Сброс опознаётся, если счётчик уменьшился, сменился `boot_id` или
  `StartedAt` контейнера; тогда разницей считается текущее значение. Отрицательных чисел и
  «петабайтов» после перезагрузки нет.
- **Хранение — по часам UTC** на пользователя: получено, отправлено, пиковая скорость за минуту.
  Сутки Москвы (UTC+3, без перехода на летнее время) складываются из целых часов. Срок — 400 дней
  (~10 МБ в год по оценке), чистка — в запуске отчёта.
- **Скорость** = разница / реальный интервал между замерами. Если интервал больше 5 мин (пропуск
  сбора), байты учитываются, а скорость за этот интервал не считается.
- **«Последний раз в сети»** — максимум из всех замеченных `latest-handshake`; переживает сбросы.
  **«В сети сейчас»** — рукопожатие моложе 180 с.
- **«Ни разу не подключался»** пишется честно: «не подключался с начала наблюдения ДД.ММ».
- **Молчание:** > 7, > 30, > 90 дней с последнего рукопожатия.
- **Удалённый пир** сохраняет историю под последним известным именем и помечается `removed_at`.
- **Имя:** `clientsTable` → `names.conf` (префикс ключа = имя) → «ключ abcd1234». Если
  `clientsTable` не читается, остаются прежние имена.
- **VPS по часам:** средний и пиковый CPU (по разнице `/proc/stat` за минуту), пик занятой памяти
  (`MemTotal − MemAvailable`), пик load1, заполнение диска, трафик WAN, `awg0` и контейнера xray,
  пик conntrack. Трафик WAN и контейнера xray включает оба плеча (клиент ↔ VPS и VPS ↔ интернет),
  поэтому примерно вдвое больше пользовательского; в отчёте подписан как трафик контейнера, а не
  пользователей. Пользовательский трафик — только счётчики пиров `awg0`.
- **События:** смена `boot_id` → «VPS не работал с … по …» (последний замер старой загрузки →
  `btime` новой) и строка причины из `journalctl -b -1`, если она там есть; перезапуск контейнеров
  `amnezia-*`; пропуски сбора; недоставленный отчёт.
- **Приватность:** адреса клиентов (endpoint), адресаты соединений, DNS не читаются и не хранятся.

### Схема БД

| Таблица | Содержимое |
|---|---|
| `peers` | `pubkey` PK, `name`, `vpn_ip`, `first_seen`, `last_handshake`, `removed_at` |
| `peer_state` | последние сырые `rx`, `tx`, `ts`, `boot_id`, `started_at` по пиру |
| `peer_hourly` | (`pubkey`, `hour_utc`) PK, `rx`, `tx`, `peak_bps` |
| `host_state` | последние сырые счётчики хоста (CPU, WAN, xray, `boot_id`, `StartedAt`) |
| `host_hourly` | `hour_utc` PK, `samples`, `cpu_sum`, `cpu_max`, `mem_max`, `load_max`, `disk_pct`, `wan_rx`, `wan_tx`, `awg_rx`, `awg_tx`, `xray_rx`, `xray_tx`, `conntrack_max` |
| `events` | `ts`, `kind`, `detail` |
| `meta` | `schema_version`, `monitoring_start`, `last_report_ok` |

Один запуск сборщика — одна транзакция: при ошибке не пишется ничего.

## 7. Отчёт

Отправка в 10:00 МСК за прошедшие московские сутки; окна 7 и 30 дней — последние полные сутки,
заканчивая вчерашними. Формат — HTML (`<pre>` для таблицы), все имена экранируются.
Макет (числа условные):


- Строки клиентов — все, у кого за сутки был трафик, по убыванию; остальные — сводными строками.

- Если вчерашний отчёт не дошёл, первая строка: «⚠️ отчёт за ДД.ММ не был доставлен».

## 8. Сбои и самоконтроль

| Сбой | Поведение |
|---|---|
| `amnezia-awg2` не запущен или `docker exec` не ответил за 10 с | событие «awg2 недоступен», учёт пиров за минуту пропускается (не нули), метрики хоста пишутся |
| `clientsTable` не разбирается | остаются прежние имена |
| Ошибка SQLite | выход с кодом ≠ 0, в журнале systemd; транзакция откатывается |
| Время пошло назад / интервал ≤ 0 | разница не считается, замер становится новой точкой отсчёта |
| Telegram не отвечает | 3 попытки (`timeout` 10 с, пауза 30/60 с), затем событие `report_failed` и строка в следующем отчёте |
| VPS выключен в 10:00 | `Persistent=true`: отчёт уходит после включения |
| Сборщик не запускался | «Сбор: N из 1440 мин» в отчёте |

Сборщик **никогда** не выполняет в контейнерах ничего, кроме постоянного скрипта чтения; `docker`
вызывается только с `exec` (этот скрипт) и `inspect`.

## 9. Безопасность и правило №13

- Корень нужен ради `docker exec`; лимиты юнита не дают сборщику отнять CPU у VPN.
- Токен — `/etc/nasa-vpnmon/telegram.env` (root, 0600). Переносится с Jetson по SSH одной
  командой без вывода значения (тот же бот и `chat_id`, что у ежедневного отчёта). В git — только
  `*.example`. Скрипт вызывает только `sendMessage`, на `getUpdates` основного бота не влияет.
- БД и `names.conf` — 0600; имена людей и ключи в git не попадают.
- Новых портов нет; `ss -tlnpu` до и после установки должен совпасть.
- **Правило №13 при установке и откате:** до и после — `StartedAt`/`RestartCount` у `amnezia-*`
  без изменений, число пиров в `wg show awg0 peers` не уменьшилось, наружу слушают только прежние порты.

## 10. Тестирование

**Модульные, без VPS** (`tests/vpn_monitor/`, в `preflight.sh` и CI как у других сервисов):
разбор вывода `wg show` и `clientsTable` (фикстуры без настоящих ключей); обычная разница;
уменьшение счётчика; смена `boot_id`; перезапуск контейнера; появление и исчезновение пира;
граница московских суток (21:00 UTC); пороги молчания; «не подключался с начала наблюдения»;
экранирование имён (`Admin [Windows 11 …]`, `<b>`); разбиение длинного отчёта; пустые сутки;
статический тест: в исходнике нет `dump`, `showconf`, `private`, а `docker` вызывается только с
`exec`/`inspect`.

**Живые, на VPS (ведущий):** `collect.py --dry-run` (печатает разобранное, не пишет в БД) совпадает
с `wg show awg0 transfer`; через 5 мин в БД есть строки; `report.py --stdout` за текущие сутки;
`report.py --send --test` — одно сообщение доставлено; `systemctl status` показывает расход CPU и
памяти на запуск; через сутки — первый настоящий отчёт. По желанию владельца — сверка объёма:
скачать 100 МБ через VPN на известном устройстве и найти их в часовой строке (±5 %).

## 11. Выкат, откат, исполнители

- **Выкат:** `install_vps.sh` кладёт скрипты и юниты, создаёт каталоги, включает таймеры; токен и
  `names.conf` — отдельными шагами ведущего. До и после — проверки правила №13.
- **Откат:** `systemctl disable --now nasa-vpnmon-collect.timer nasa-vpnmon-report.timer`, удалить
  юниты, `/usr/local/lib/nasa-vpnmon`, `/etc/nasa-vpnmon`, `/var/lib/nasa-vpnmon`. VPN не задет.
- **Исполнители (правило №16):** реализация по плану — субагент Sonnet (TDD); английская пара
  спецификации и runbook — DeepSeek; установка на VPS, перенос токена, живые проверки и приёмка —
  только ведущий (VPS — критичная зона).
- После выката: правка `CLAUDE.md` (21 пир, простой 04.10, новый юнит) в паре RU/EN.

## 12. Ответы владельца на открытые вопросы (2026-10-04)

1. Пиры `.18–.22` в `names.conf` — **«запасной-1» … «запасной-5»**; `.17` — «Vostro».
