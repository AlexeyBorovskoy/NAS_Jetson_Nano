## Stage-0 блокеры

### NAS-REG-001 — незакоммиченная правка шлюза ломает чат и картинки

Severity: **P0 (блокер коммита/деплоя)** · Confidence: CONFIRMED (исполнено) · Component: LLM Gateway

**Observation.** В staged-версии `services/llm-gateway/app/main.py` smart routing вызывает
`_is_complex_prompt(full)` (staged `:889`) до присваивания `full` (staged `:922`). Любой запрос с
`provider=gigachat` — а это провайдер по умолчанию (ADR-0008) — даёт `UnboundLocalError` → HTTP 500.
В WIP-правке (G01, ограничение `save_path`) строка `_IMG_TAG_RE = re.compile(...)` заменена новым
блоком, а использование осталось (WIP `:636`) → `NameError` в генерации/редактировании картинок.
Там же `_IMAGE_OUTPUT_ROOT.mkdir(...)` на импорте модуля (WIP `:490`): при запуске тестов на Windows
создаёт `\data\images` в корне текущего диска; в контейнере без прав на `/data` — падение при старте.

**Evidence.** `TestClient` на трёх версиях с подменённым `_call_gigachat`:
HEAD → `200`; staged → `500`; WIP → `500`. Полный набор `tests/llm_gateway` на staged:
`2 failed, 19 passed` (`test_default_provider_is_gigachat`, `test_giga_failover_to_deepseek`).
Новые 8 тестов smart routing проверяют только `_is_complex_prompt`, не эндпоинт.

**Impact.** Выкат превратит `@бобик` в «🐕 Не смог получить ответ» для всех. На устройстве сейчас
старый код (`/health` без `smart_routing_enabled`) — **боевой ущерб нулевой**.

**Root cause.** Тесты новой функции вместо теста поведения эндпоинта; утверждение «все тесты прошли»
относилось к новому файлу.

**Recommendation.** Вычислять `full` до выбора модели; вернуть `_IMG_TAG_RE`; создавать каталог
лениво в `_finish_image`; добавить тест `POST /v1/chat` (gigachat, мок) и `POST /v1/image/generate`
(мок) в тот же набор. Регэкспы smart routing: `\bошибк\b`, `\bтемператур\b`, `\bвосстановлен\b`,
`\bconfigur\b` никогда не совпадут со словами (граница слова после основы) — заменить на `\bошибк\w*`;
убрать дубли (`nginx` ×3, `config` ×2, `tunnel` ×2).

**Verification.** `python -m pytest tests/llm_gateway tests/unit -q` — 0 failed; ручной `TestClient` → 200.
**Effort:** S.

**Обновление 2026-09-19 ~04:10 UTC.** Во время аудита правка была **закоммичена и запушена** в `main`
(`d52c11b feat(w0.1)…`, `d1bebc4 docs: CHECKPOINT_2026-09-19`). Перепроверено на `d52c11b`:
`_is_complex_prompt(full)` на `:957`, `full =` на `:990` → чат 500; `_IMG_TAG_RE` отсутствует;
`tests/llm_gateway` → те же 2 падения. `CHECKPOINT_2026-09-19.md:29` утверждает «все 16 прошли».
На устройстве по-прежнему старый код (контейнер шлюза запущен 2026-09-18 13:58, `/health` без новых полей).
**Почему ворота пропустили:** `scripts/quality/preflight.sh:183-202` запускает только `tests/unit/test_*.py`;
`tests/llm_gateway` pre-commit не видит. Это отдельная дыра ворот (см. NAS-QA-001). **Деплоить `main`
в текущем виде нельзя.**

## Security

### NAS-SEC-001 — диагностика NAS API без авторизации + `CORS *`
Severity: P1 · Confidence: CONFIRMED (live) · CWE-306, CWE-942
Live без токена: `/v1/status 200`, `/v1/metrics 200`, `/v1/containers 200`, `/v1/logs 200`,
`/v1/talk/bot/status 200`, `/v1/talk/rooms 200` (9 комнат: имя, участники, токен). Заголовок
`access-control-allow-origin: *` (`nas_jetson_nano-api/app/main.py:183`). `POST /v1/report/now` —
«Авторизация не требуется» (`routers/actions.py:75-86`, не вызывался). Любая страница, открытая в
браузере домочадца дома или под VPN, может прочитать эти ответы и отправить наружу.
**Recommendation:** `require_auth` на всё кроме `/healthcheck`; CORS — явный список или выключить.
**Effort:** S.

### NAS-SEC-002 — authN ≠ authZ, docker.sock
Severity: P1 · Confidence: CONFIRMED (код) · CWE-285
`routers/auth.py:99-111` — зависимость проверяет только подпись JWT; вход по паролю любого
пользователя Nextcloud (5 учёток). После входа доступны `POST /v1/actions/containers/{name}/restart`
(включая `homecloud_nextcloud_db`) и `/v1/actions/backup/now`. Контейнер держит `/var/run/docker.sock`
— монтирование `:ro` не ограничивает Docker API. **Recommendation:** роли owner/family из списка в
конфиге; действия — только owner; для docker — прокси с allowlist (например, только `restart` для
перечня). **Effort:** M.

### NAS-SEC-003 — LLM Gateway: без auth, `save_path`, квоты, fail-open
Severity: P1 · Confidence: CONFIRMED (исполнено на HEAD) · CWE-306, CWE-22, CWE-639
- Нет аутентификации; порт `0.0.0.0:8090`, проброшен на VPS для VPN-клиентов.
- `_finish_image` пишет по клиентскому `save_path` (`main.py:923-933`) в контейнере от root; persistent
  том `/data` содержит `llm_usage.json`. Содержимое записи — картинка провайдера, не данные атакующего:
  это порча/DoS, не RCE.
- Квота «на человека» по полю `user` из тела (`:800`) — `olga` получила 429, `olga2` — 200.
- `_load_usage` (`:112-116`) при ошибке чтения возвращает `{}`: испорченный файл → счётчики обнулены
  (исполнено: `day_tokens` → 0). Запись не атомарна (`:122`).
**Recommendation:** сервисный токен (заголовок) для `/v1/*`, `user` — из токена; `save_path` — только
имя файла в фиксированном каталоге (WIP-правка — верное направление); атомарная запись
(`tmp` + `os.replace`) и 503 при нечитаемом файле. **Effort:** M.

### NAS-SEC-004 — fallback в DeepSeek на ошибках авторизации Giga
Severity: P2 · Confidence: CONFIRMED (исполнено)
Любой не-200 от Giga и ошибка OAuth маппятся в 502 (`main.py:359`, OAuth выше), а fallback срабатывает
на `(429, 502, 503)` (`:821`). Мок «HTTP 401» → ответ от `deepseek`, `fallback_from=gigachat`.
Ошибка конфигурации (просроченный ключ) незаметно уводит семейные вопросы ко второму зарубежному
провайдеру. **Recommendation:** различать 401/403/4xx (без fallback) и 429/5xx/транспорт. **Effort:** S.

### NAS-SEC-005 — SSH по паролю и повторное использование пароля
Severity: P2 · Confidence: CONFIRMED
`sshd -T`: `passwordauthentication yes`, `permitrootlogin without-password`. sudo-пароль admin =
пароль администратора Nextcloud (зафиксировано в `CLAUDE.md` как рабочий приём). Компрометация
Nextcloud-админа = root на хосте через LAN-SSH. **Recommendation:** `PasswordAuthentication no`
(доступ по ключу уже работает) — **только** после проверки второго пути входа; развести пароли. **Effort:** S.

### NAS-SEC-006 — Portainer и Netdata в LAN
Severity: P2 · Confidence: CONFIRMED
Portainer (docker.sock) на `0.0.0.0:9000/9443`; Netdata (`CAP_SYS_ADMIN`, `SYS_PTRACE`, docker.sock)
без авторизации на `:19999` (live 200). Сегментации LAN нет (Wi-Fi гость видит всё).
**Recommendation:** Portainer поднимать по требованию или только на `127.0.0.1` + SSH-туннель; Netdata —
заменить Beszel/Kuma или привязать к `127.0.0.1`. **Effort:** S.

### NAS-SEC-007 — лишние сервисы хоста
Severity: P3 · rpcbind на `0.0.0.0:111` (TCP/UDP), avahi `5353`. NFS не используется. Отключить.

### NAS-SEC-008 — идентификаторы в публичном репозитории (G05)
Severity: P2 · Confidence: CONFIRMED
`CLAUDE.md` (таблица «Личные комнаты Talk» с токенами комнат, логины членов семьи, адрес роутера),

**Recommendation:** перенести в `docs/local/` (вне git); история — отдельным решением.

### NAS-SEC-009 — картинки `@бобик` до safety gate, без лимита размера (G08/G09)
Severity: P2 · Confidence: CONFIRMED (код)
