## 4. План развития — оценка

**Что правильно.** Волна W0.5 взята из аудита, у пунктов есть критерии проверки, деплой только по
команде, список «чего не делать» разумный (без Kubernetes, без семейных фото во внешние LLM, без
мутаций АСУДД в `@бобик`).

**Что не так.**
1. **Приоритеты по одному источнику.** Весь план построен на `audit_new.md` (G01–G24 — код и политика).
   В нём нет найденного на живой системе: сломанное авто-восстановление SSD, обесточивание 18.09, файлы
   Nextcloud / `config.php` / `.env` без копий, HDD-копия доступна на запись семье, ≈8 ГБ/сутки на SD,
   CI красный 35 прогонов, дыра в воротах. Для семейного NAS риск **потерять данные** выше риска
   «кто-то в LAN потратит квоту»: R0-02, R4-01, R4-02 из `ROADMAP_2026-09-19.md` должны идти рядом с H01–H04.
2. **В hardening-спринт смешаны фичи.** H15/H16 (smart routing, пресеты) — не hardening, и именно фича
   внесла P0. Фичи — отдельной волной, после зелёного набора тестов.
3. **Шаг W0.2 спроектирован без вызывающих.** Токен добавлен в шлюз, но не в Talk-бот, daily report и
   скрипт баланса; fail-open по умолчанию. Правильный порядок: вызывающие умеют слать токен → токен
   на устройстве → шлюз fail-closed.
4. **Нет критерия «готово = проверено».** Статус ставится по факту коммита. Нужен явный DoD: весь
   `tests/` зелёный локально и в CI, эндпоинт проверен `TestClient`, числа из вывода, а не по памяти.

**Исследовательское направление (`research/`).** Оба файла — **промпты** для других моделей (Grok и
др.), а не результаты исследования. «Multi-Provider Photo AI Orchestrator» (Kaggle / Modal / Colab /
Lightning / HF как воркеры для фотографий, уровень `PREVIEW_ALLOWED` для «обычных фотографий»)
противоречит `AGENTS.md` (жёсткое ограничение п. 4 («не отправлять личные фото во внешний LLM»)), требует принятия риска
по ADR-0010 и сам мастер-промпт аудита (§40–41) допускает внешние бесплатные ресурсы только для
stateless-задач с публичными/несекретными данными. В семейном архиве «обычных» фотографий по сути
нет. Реалистичный путь: локальный воркер на станции батчем через обратный туннель (ROG-пилот уже
подготовлен), внешние GPU — только для экспериментов на несемейных данных. Как исследование держать
можно; в план развития — нет.

### English summary
The direction is right (small security steps, no deploy without the owner's command), but execution
was not verified. The audit's P0 (GigaChat chat → 500) is still present, and the new uncommitted W0.2
adds a regression: endpoints became `async` while calling blocking HTTP/locks, so `/health` waits for
in-flight LLM calls (6.0 s vs 0.5 s measured). The service token is fail-open, and no caller sends it.
Tests: 5 failed / 26 passed, including GigaCode's own new tests. Status docs claim "all passed / ✅".
Smart-routing regexes never match Russian words, and Max has a separate, 10× smaller quota. The plan
relies on one code audit and misses live operational P1s (broken SSD recovery, backup gaps, power loss).
The Photo AI Orchestrator research sends family photos to free external GPUs, which conflicts with
`AGENTS.md` and ADR-0010. Keep it as research only.
